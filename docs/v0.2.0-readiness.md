# v0.2.0 readiness (P1 workbench)

**Date:** 2026-10-29  
**Branch:** `feat/p1-workbench`  
**Scope:** the P1 workbench slice: full-list `session.panel`, durable section collapse, and verified true totals.

## Verdict

**Ready for `0.2.0` once this branch is merged and tagged.** The installed plugin was exercised against
OpenCode `2.2.0` and live GitHub data: the panel opens from both the sidebar control and
`ctrl+shift+g`, its keys navigate, filter, launch, refresh, go fullscreen, open the canonical URL, and
close; section collapse survives a TUI restart; and a reduced `fetchLimit` proves the panel's totals
come from GitHub while the sidebar keeps its own bounded rows. The full hermetic suite, audit, and pack
check pass.

## What changed

| Area           | Change                                                                                                                                                                              |
| -------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Server         | `summary({ force, full })`. The cache stores one full normalized snapshot; `full: true` returns every row fetched under `fetchLimit`, the default returns the bounded sidebar rows. |
| Sidebar        | Section collapse is stored in `context.storage.store("preferences")`; `display.collapsed` seeds the first run only. The header gains a `▤` panel control.                           |
| Panel          | New `session.panel` contribution (`src/tui/panel.tsx`) with mine/all filters, true-total headers, `showing N of TOTAL`, row selection, and a focused keymap layer.                  |
| Global command | `github.panel.open` on `ctrl+shift+g` through the `app` slot. It refuses non-session routes and child sessions.                                                                     |
| Shared UI      | `StatusLine` moved to `src/tui/status-line.tsx`; `Row`/`PullRow`/`IssueRow` accept an id and selected state.                                                                        |

## Releasing 0.2.0

1. Merge the release PR to `main`, then tag the merged commit:

   ```sh
   git switch main && git pull --ff-only
   git tag -a v0.2.0 -m "v0.2.0"
   git push origin v0.2.0
   ```

2. `.github/workflows/publish.yml` runs `bun run check` and `bun run pack:check`, publishes with
   provenance, waits for the version on the registry, and creates the GitHub release. It uses
   `NPM_TOKEN` while present and falls back to the workflow's OIDC identity otherwise.
3. If the tag run fails after a successful publish, or npm reports `TLOG_CREATE_ENTRY_ERROR`, dispatch
   the workflow with the existing tag. Do not republish an immutable version; use the retry path that
   checks the registry first.
4. Verify the registry tarball, not just the local directory:

   ```sh
   NPM_CONFIG_MIN_RELEASE_AGE=0 bun add opencode-nexusnv-github-sidebar@0.2.0 --cwd /tmp/opencode/verify-0.2.0
   npm audit signatures --prefix /tmp/opencode/verify-0.2.0
   ```

   Then start a TUI against that install and confirm the panel, the keys, and a persisted collapse.

Trusted publishing still needs the npm web UI (interactive 2FA): add a GitHub Actions trusted
publisher for `nexusnv/opencode-nexusnv-github-sidebar` and `.github/workflows/publish.yml`, then
delete the `NPM_TOKEN` secret.

and the provenance/signature history.
